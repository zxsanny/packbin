# Dart: compact text strings and the generated code tables

**Task**: AZ-4137_dart_text
**Name**: Dart: compact text strings and the generated code tables
**Description**: The compact text codec in Dart, its generated tables and the shared text vectors.
**Complexity**: 3 points
**Dependencies**: AZ-4134_dart_core
**Component**: dart
**Tracker**: AZ-4137
**Epic**: AZ-4133

## Problem

`utf8` fields use the compact text format (ADR-006). Dart needs the encoder and decoder with the frozen code tables, generated by the same script as the other packages so the tables cannot drift.

Feature criteria, scenarios and decisions: `_docs/02_task_plans/dart-package/` (`acceptance_criteria.md` DT-1 to DT-20, `scenarios.md`, `problem.md` D-1 to D-5 and A-1 to A-7, `task_map.md` for the write sets).

## Outcome

- Every row of `fixtures/text/vectors.txt` passes in Dart.
- The Dart tables are emitted by `scripts/text/emit_tables.py` and checked by `check-emitted.sh`.

## Scope

### Included

- A standalone text codec (encode a `String` to bytes, decode bytes to a `String` or an error value) under `dart/lib/src/text*`.
- A `dart` branch in `scripts/text/emit_tables.py` writing the generated tables file (marked as generated, not edited by hand), and Dart in `scripts/text/check-emitted.sh` and its test.
- A loader of `fixtures/text/vectors.txt` and tests for the rows `enc`, `alt`, `bad`, `ref`, `flip`.
- Owns: `dart/lib/src/text*`, `dart/test/text*`, `scripts/text/**`.

### Excluded

- The `utf8` field in a scheme (AZ-4138 wires the codec into the walker)
- `list` and `dict` (AZ-4138)

## Acceptance Criteria

**AC-1: Text vectors (DT-17)**
Given every row of `fixtures/text/vectors.txt`
When encoded or decoded as the row says
Then `enc`: the row's bytes; `alt`: decodes to the row's text; `bad`: an error value; `ref` and `flip` as the fixture README states; mismatches 0

**AC-2: Generated tables (DT-17)**
Given `fixtures/text/tables.json`
When `emit_tables.py` runs for Dart and `check-emitted.sh` runs
Then the committed Dart tables file equals the emitted one; a hand edit of one table entry makes `check-emitted.sh` fail

**AC-3: Hostile text**
Given a payload whose length says more bytes than are left, an unpaired surrogate in a Dart `String`, and invalid code sequences
When decoded or encoded
Then an error value on decode; a thrown pack error on encode of the unpaired surrogate (as TypeScript); exceptions from decode 0

**AC-4: Empty string (zero value)**
Given an empty `String`
When encoded and decoded
Then the bytes the `enc` row for the empty text gives; decodes to an empty `String`, not `null`

## Constraints

- The tables are part of the wire format: generated only, never typed by hand.
- Other loaders read `fixtures/text/vectors.txt` by position: this task adds no row and changes no fixture.
- No file over 500 lines.
- The codec has no dependency on the walker, so it can be built beside AZ-4135.

## Risks & Mitigation

**Risk 1: Dart strings are UTF-16**
- *Risk*: Code-point work on a `String` needs `runes`; a lone surrogate is legal in a `String`.
- *Mitigation*: The encoder walks runes and refuses a lone surrogate; the vectors' `bad` rows and one extra test cover it.
