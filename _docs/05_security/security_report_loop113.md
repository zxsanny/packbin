**F79** (Low / A06). Description: while a repeat is open each level asks for the first writer below it again; no memo as in TypeScript and Dart. Measured: Java 9 ms at depth 1,000, 118 ms at 3,500 (23 ms before), 438 ms at 8,000; C# 336 ms at 8,000 (13 ms before); both fail on the stack first (Java at about 4,000, C# at 16,000, same as before), so the worst case measured is under a second (Java 600 ms before the overflow at 9,000). Go has a growable stack (up to 1 GB), so its depth is not stack-bound; not measured. Impact: only an application that builds a scheme of thousands of nested `when` or groups from outside data (none of the nine packages has a loader) could stall its own build. Remediation: keep the first writer per node (TypeScript `writers`, Dart `_held`) or return it from the one pass.
**F80** (Low, found by the sanitizer run, pre-existing, test only). `std::uint8_t out[16]` then `pack(p4, row, out, 17)`: `ecc::protect` writes the 17th byte (ASan stack-buffer-overflow, `ecc.hpp:172`); the library respects the capacity it is given. Remediation: `out[17]`; until then an ASan run of the host suite stops at `ecc_api_tests`.

## Recommendations
- Immediate: none. Short-term: memoize the first writer in Java, C# and Go (F79); declare `out[17]` in the ECC test (F80). Long-term: add a depth case to the three cost tests (TypeScript, Dart and Swift test siblings only) and run the C++ host suite under ASan in CI.
