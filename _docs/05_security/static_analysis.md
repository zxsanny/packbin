## Loop 15

### Round limits (F10): where the check sits and what is allocated before it

| Check | Result |
|-------|--------|
| Check before per-round storage, every way a round starts | C#: `Walker.cs:292` (repeat) and `Walker.Counted.cs:273` (times) call `Budget.TryStartRound` before `new Scope`; Java: `Rounds.java:50,70` before `unpackRound`; TypeScript: `walker.ts:131,191` before `const one: Value = {}`; Rust: `unpack.rs:212,358` before `Values::with_capacity`. Every round is a round of one of those two field kinds, so dispatch, sessions and typed Rust rows (`Scheme::unpack` calls `walk::unpack(&layout)`, `scheme/mod.rs:278`) all pass through them. A `repeat` or `times` in a list or dict element is reached with the same budget object (C# `Walker.Counted.cs:365,436`; Java `Containers.java` passes `cur`; TypeScript `walker.ts` passes `cur`) |
| One budget per unpack call, never shared | C# `new RoundBudget` in `ReadFields` (`Packbin.cs:192`), not static; TypeScript fresh `cur` in `unpackBody` (`walker.ts:276-283`); Java `new Cursor` in `decode` (`BinaryPacker.java:62`); Rust `Cursor::new` in `unpack` (`unpack.rs:445`). `PackSession.unpack` calls the same entry in all four. A scheme's limits are read from the matched handler's scheme (`index.ts:148`, `Packbin.cs:64`, `BinaryPacker.dispatch`) |
| Preallocation from a count the packet states | none before a bytes-left check. C#: `FitsItems` (`Walker.Counted.cs:90-99`) before `new List<int>(count)` (`:192,252`); `Math.Min(count, bytes.Length - offset)` for list and dict (`:362,422`); `sized` copies after `left < ByteCount`. TypeScript: `readBits`, `readPacked`, `readSized` check `left < nbytes` first and push without a capacity (`kinds.ts:121-160`); `new Array<number>(n)` only in pack with `n` from the scheme. Java: `nbytes > left` before `new ArrayList<>(count)` (`VarFields.java:148-154,212-218`) and `count > left` before `new byte[count]` (`:62-71`). Rust: `cur.take(nbytes)` before `Vec::with_capacity(n)` (`unpack.rs:286-287,325-326`), `capacity_hint = count.min(left)` for list (`element.rs`, `unpack.rs:402`), no capacity for the times `rounds` vector. A `times` count of 4,000,000,000 with 3 bytes left failed in 20 microseconds at 1.6 MB resident (Rust probe) and in 1 ms at baseline in TypeScript |
| Limit arithmetic | C# `slots > maxSlots - _slotsUsed` (`Scope.cs:33`), `_slotsUsed` is added to only after that test, so it never exceeds `maxSlots` (`long`); `rounds++` (`int`) is bounded by the packet length. Java `Cursor.startRound` likewise (`Cursor.java:21`). Rust `round_slots > self.max_slots - self.slots` (`unpack.rs:39`, `usize`, no underflow by the same invariant; `usize::MAX` valid). TypeScript `cur.slots + width > cur.maxSlots` with safe integers: a sum past 2^53 still compares greater, so it refuses. No overflow found |
| Zero-width rounds | a round that reads nothing is an error before it can repeat (`Walker.cs:303`, `Walker.Counted.cs:284`, `Rounds.java:58,78`, `walker.ts:138,197`, `unpack.rs:226,371`), so a round with 0 slots still costs a packet byte and is capped by `maxRounds` |
| Refusal contents | `ShortPacket` or the package's interim error with the round field's label (Rust: `"repeat"` or `"times"`), `needed` 0, `left` = bytes left at that round. No packet byte appears; `left` is derivable from the length the sender chose. The refusal is the same shape as every other unreadable value, so it is no extra oracle; the limits are set by the scheme author, not the packet, so an attacker cannot move them |
| What a scheme author gains | nothing against the receiver: limits only refuse. A malicious scheme author already controls the receiver's code. A limit of 1 is a legitimate strict scheme; the only effect is that legitimate packets with more rounds are refused (availability change on upgrade, stated in the README) |
| New panic or throw | Rust `with_limits(0, _)` and `(_, 0)` panic (`map_scheme.rs:77-83`) at scheme construction; the arguments are the scheme author's, no packet reaches it. C# `ArgumentOutOfRangeException`, TypeScript `RangeError`, Java `IllegalArgumentException` likewise at `WithLimits`. C# `Scope.Budget` throws `InvalidOperationException` for a scope without a budget (`Scope.cs:15`); every unpack scope is created with one (all `new Scope(` sites checked), pack scopes never call it. No new exception on a packet path |
| Residue not covered by the limits | `bits` and `packed` counts come from an integer field and are bounded only by the bytes left, 8 or 4 items per byte; a 1 MiB packet decodes to 8,388,608 items (Rust 270 MB, TypeScript 233 MB, C# and Java 38 MB, Python 79 MB, net). List and dict elements read at least one byte each (`Walker.Counted.cs:371`, `walker.ts:223,244`, `Containers.java:170`, `element.rs:8-10`), so they are bounded by bytes left and by u16 per container. Both are linear in the packet; see F10 in `security_report.md` |

Probe results (scratch copy, net resident set over a bare runtime): 36-name body, 1 MiB, defaults: C# 45 MB refused, Java 54 MB, TypeScript 1 MB (Node baseline 87 MB); limits lifted: C# 510 MB, Java 554 MB, TypeScript 334 MB. 300-name body with every name set, packet sized to hit the 4,194,304-slot limit: C# 192 MB, Java 353 MB, TypeScript 132 MB. Rust, one-byte rounds with 8 flag bits: 66 MB refused; 64 set flag bits per round: 431 MB refused at the slot limit; lifted limits, 8 flag bits: 1.0 GB.
