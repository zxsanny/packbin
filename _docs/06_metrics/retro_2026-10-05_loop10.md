## What went well

- The embedded job found a memory fault (F0) that 20 M sanitizer-checked fuzz packets on a 64-bit host could not.
- An independent review of batch 5 found a slow path and a stack-margin risk before the commit.
- The 36 bug-fix specs were filed and renamed to ticket ids in one pass, so loops 11 onward start from a clean hopper.

## What to change

- Add a 32-bit fuzz or sanitizer build (QEMU user, arm) to the embedded job so count narrowing is checked on every push.
- The stack budget has 24 B of margin; the next change that deepens the unpack recursion must free stack first.
- Spec examples with order ids need a run through `validate` before they are written (the AZ-2081 AC-2 example was already invalid for an id reason).

## Open for the user

- UTF-8 validation in the C++ core (`invalid_utf8*` vectors) and the error labels (C15).
- Project AC-8 wording ("names the field and the bytes remaining") against the C++ `Result`.
- AC-12 (install by registry name) needs a published tag and registry tokens.
