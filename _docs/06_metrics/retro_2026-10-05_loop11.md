## What went well

- Five language workers in parallel with disjoint write sets produced 16 tickets in about two and a quarter hours with no merge conflict; the one `git stash` was caught and verified harmless.
- The assessment round turned an unspoken risk (65 535 x 65 535 empty list rounds, 131 KB packet) into a decided rule (U1) and five tickets before it reached a release.
- The auditor's scratch fuzz (276 855 hostile packets per package, 45 schemes, cross-package differential) found F4, F5 and F6, which eight reviewer reports had not; the same corpus re-verified the fixes with zero regressions.
- The reviewer FAIL in batch 3 was a true catch: four TypeScript call sites ran correctly but failed `tsc --noEmit --strict`.

## What to change

- Add a typecheck job (`tsc --noEmit --strict` over `typescript/src`) to `.github/workflows/test.yml` and the CI-parity gate; today a type error passes both the tests and CI.
- Before accepting a hostile-input fix, run its new test against the pre-fix tree (or `git archive` of HEAD in the scratchpad) and require it to fail; spec-literal packets (`01ffffffff`) passed on the old code in several packages.
- Keep the audit's fuzz generators (`gen.py`, the per-language drivers, `cmp.py`) in the repo (for example under `fixtures/hostile/fuzz/`) instead of the scratchpad, and run them on each loop that touches unpack. They were the most effective check this loop and are lost when the session ends.
- Worker prompts: add "no `git stash`, `checkout`, `reset`" next to "do not commit".
- Number the owner decisions in the spec (zero-width `times` had no AC in any spec; the audit and the assessment both had to find it in a batch report).
- Cross-package divergence is the dominant defect class (F5, F6, F4, U2): put each cross-package example (`01 01 0a`, the `__proto__` key, `01 ff*8`) into `fixtures/hostile/cases.txt` so the six suites run it, not one package.
