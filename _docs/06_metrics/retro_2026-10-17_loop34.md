## Top 3 improvement actions

1. **A spike must restore the way the real cache does.** The intake spike's plain `tar` round trip kept file times to the second, so SwiftPM rebuilt all of BoringSSL, and the loop added ccache for a problem CI does not have (`actions/cache` keeps nanosecond times; run A asked ccache 0 times). Round-trip with `tar --posix` or the real action, and read one CI run before adding a tool on a spike's word.
2. **Put the build's configuration in an exact cache key.** A hit never saves, so entries built another way stay: after ccache was removed, every hit recompiled BoringSSL with plain clang (run B, 75 s instead of 17 s). The keys now hash `run-suite.sh` and `ring-swift.sh`.
3. **Run every reader of a changed shape, and keep a budget of API calls.** `report-row.test.sh` also parsed the `suites` matrix and failed at step 11 (CI's scaffold would have); and a 30 s run watcher used the 60 unauthenticated calls an hour twice, so polls failed and read as "running". Grep the readers before the commit; poll at 60 s with one call per tick and check `/rate_limit` on a failed poll.

## Suggested rule or skill updates

- Long-running-jobs rule: an empty or error poll answer from a rate-limited API is "poll failed", never the job's state (the watcher printed "running" for failed polls).
