## What went well

- Each batch kept the build checks and the tests in the same commit; every AC has a test and a negative proof (a mutation, a violating temp copy or a fabricated artifact), and the gate test would have failed 10 times with one table row flipped.
- The high-effort review of AZ-2096 found a real partial-release path (`ls-remote` under pipefail) and the token-lifetime ordering that the worker's own scenarios could not show.
- The Pico example now has two real results on this host (GCC 9.3.1 on arm64, GCC 9.2.1 under amd64 emulation), with 0 packbin warnings, so the "not run" row of loops 12 and 13 is closed for this host.
- The assessment recorded 32 covered rows with AC + test + code path, and the three open questions came with options and a recommendation.

## What to change

- Size CI and publish restructures by scripts and tests touched, not by the number of ACs: AZ-2096 was 3 points and became 15 files and +1 313 lines.
- A fresh `/code-review` for every batch that changes a script running with credentials; the two batches the parent read alone found nothing, but the one that got the high review found two Mediums.
- Pin or verify every tool that runs in the credentialed job (F12) and give the build step no write access to the scripts the host runs next (F13).
- Write down the host recipe: strict `tsc` flags, `PACKBIN_CXX_SYSROOT`, the Pico amd64 container.
