## Top 3 Improvement Actions

1. **Survey every package before fixing a cross-package inconsistency a review names in some.** The dispatch check order took three loops: the loop 38 review named the duplicate-type order in five packages, loop 39 moved them, its review found four more order differences, and loop 40's survey of all eight found Java, C# and Python differed too. One table of call x check x package before the first fix would have closed it in loop 39.
   - Impact: one cleanup loop instead of two (about 3 points and one step 11 run of about 20 minutes)
   - Effort: low
2. **Make every suite timing bound load-aware.** Fixed-second bounds failed under pool load in 6 suite runs (the serial retry hid them) and on the slower CI runner twice after loop 38 added about 5 % to pack and unpack. The Python AC-10 fix (`75b1d39`, the bound scales with a stdlib reference loop run in the same process) is the model; Go text times, Rust debug NFR, Python EC-13, TypeScript `round-scope-cost` and Java AC-8 still use fixed bounds.
   - Impact: no red CI from timing, step 11 without serial retries (each retry costs a suite's time again)
   - Effort: medium (one helper per package)
3. **Offer carried owner-run skills as hopper options, not leftovers.** `/security` (AZ-2666), `/feature-assess` and this retro were written as "owner-run" in five records and never ran; the owner took the audit at once when the loop 41 intake offered it.
   - Impact: audits and retros run on their predicates instead of drifting
   - Effort: low
