## Top 3 improvement actions

1. **Ship the timing before the split.** Batch 1 split by estimate and the first CI run moved the floor (embedded 360 s, the swift gate group 215 s); only the second push, built from measured seconds, brought the wall to 344 s. A CI speed loop should plan "notices first, regroup from numbers" as two pushes and ask the owner for the second round up front.
2. **Watchers must not end in a buffering stage.** The step 11 monitor ended in `cut` and delivered nothing for 30 minutes while a healthy run finished, the failure the long-jobs rule names; an expiry with no events means the watcher is broken, not that the job is quiet. Added to `AGENT_GOTCHAS.md`.
3. **Hold a list that is split across jobs to one place with a guard that derives the set.** `publish-jobs.test.sh` (gate jobs = every `publish-gate-*`, embedded jobs = every `embedded-*`), `run-parts.test.sh` and `run-suite-swift.test.sh` keep each group, target and Swift step in exactly one job and survived two regroupings with only list edits; a guard that names jobs by hand breaks at every regroup (the timing self-test's four hardcoded names are derived now).

## Suggested rule or skill updates

- `autodev` step 11 guidance: a monitor on a log file uses `grep --line-buffered` only (`sed -u` if it must edit); the plan row for a long stage names the heartbeat source.
- `new-task` for a CI speed spec: list "the next long pole after the split" as an expected finding, so the second round is in the estimate (this loop: 5 points planned, about 8 done).
