## Top 3 Improvement Actions

1. **Time the case in every package before a speed criterion is written for all of them.** HD-2's "1 s for 200 rounds" held in Python and TypeScript by a cache, and the first run in the other packages missed it in 2 of 4: Java 2.9 s and C++ 1.9 s (Rust and C# passed). It cost a production change, an owner decision and a ticket (AZ-2742).
   - Impact: a speed criterion states the measured figure per package instead of one nominal number
   - Effort: low (one idle run per package at assessment time)
2. **Do not set a pool-run bound under about 2.5 times the idle figure.** The C++ host run failed its first pool run at load 45 with 3.538 s against 3.331 s: the load factor of the short reference loop was 1.11 while the case ran 2.1 times its idle 1.66 s. It passed on the serial retry (53 s).
   - Impact: first-run green without a retry (a retry repeats a suite's time)
   - Effort: low (a bound in the test, or the speed check only in the serial phase)
3. **Plan the split of `language-pair.sh` before the next ring row.** It is 545 lines and the two wiring self-tests (`ring-wiring.test.sh` at exactly 500, `ring-wiring-swift.test.sh` at 467) match its exact lines, so a split is a task of its own; the all-language session-ecc check already sits in the Swift test for lack of room.
   - Impact: no further growth over the cap; the checks sit in the file named for them
   - Effort: medium
