## Efficiency

- The probe-first rule worked again: the porters compared each TypeScript table row with Go's outcome before writing the walker, and the differences were either owner decisions (Go-1 to Go-4 asked as one batch each) or reported rows (24 batch discoveries became the assessment's D1 to D7).
- Slicing: a reference-table port in dependency order (core, checks, rounds, collections, limits) with the disjoint CI, ring, release and README workers beside it kept up to three workers busy; the session was written in a `git archive` scratch copy while limits changed the real tree, and merged by copying five files (4 minutes of worker time, no conflicts).
- The total review judged the list/dict element memory as "known design" (about 300 times per element) from reading; the audit measured 1.16 GB and 1.2 GB at 256 members. The estimate was a factor off by the declared width because the size hint came from the scheme.
- Step 11 ran in 25 minutes (loop 22: hours): load stayed under 40 except for a few minutes when the C++ build and the auditor's probes overlapped; no timing test failed in the run. The embedded stage cost 260 s instead of 8 s because the host Docker had been restarted and the image was gone.
- Two harness slips cost a re-run each: a `go test` result is `ok<TAB>pkg`, not `ok pkg` (stage 2 marked FAIL at exit 0, verified by the report row), and a 1-second retry window measured with bash `SECONDS` ended after one try in 2 of 8 runs.

## Lessons

- A container sized by a count taken from the scheme (declared members) instead of from the bytes read multiplies a small packet by the scheme width: Go's list of `Nested` rows peaked at 1.16 GB for a 64 KB packet with 256 members. Size from bytes already read, and measure peak allocation for every collection of rows in the review, not by estimate.
- A timing bound belongs to the build it describes: the 1 s AC-10 loop was asserted under the race detector (about 5x slower) and failed at load 80 and 87; assert it in a second run without `-race`, and let the race run only check races.
- A shared docker image cache is not durable between loops: the embedded image was gone after a Docker restart and its stage took 260 s instead of 8 s; budget a cold build and do not read a quiet log as a hang. A retry window measured in whole seconds (`SECONDS`) needs at least 3 s to guarantee two tries.
