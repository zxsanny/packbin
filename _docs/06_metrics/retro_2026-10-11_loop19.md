## Lessons

- A spec can contradict its own reference table (AZ-2331 AC-3 against the loop 18 row `W-split-false-body-given`): six workers split two literal / four narrow. One cross-package table after wave 1 and one owner question settled it; three small follow-up workers aligned C#, Rust and Python. Cost avoided by catching the contradiction at spec time: check each AC against the reference rows before the specs are written.
- The total review found six Medium defects that every package suite passed (Java `intValue()` before the cap check, a C# regression in a row that used to pack, a C++ legitimate row now refused). Reviewers that probe with a hostile value outside the type's range found the Java and C++ ones; keep that instruction in every reviewer prompt.
- A cap on one count is not a bound on the output: the security audit measured 4.29 GB written for a 64 KB request through a lone `utf8` under one `times` (F28). The loop 18 lesson ("bound a broadcast in the same change") was applied to the count only.
- The first pass of the total test run failed twice on the host (ring: Apple `python3` 3.9; publish gate: no `PACKBIN_CXX_SYSROOT`, same Python). The recipe is now in `AGENT_GOTCHAS.md` and in the smoke script.
