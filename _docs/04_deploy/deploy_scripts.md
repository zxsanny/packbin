# Deploy scripts

No `scripts/deploy.sh`. The publisher is `.github/workflows/publish.yml`, which runs on a `v*` tag after the called `test.yml` jobs pass and `publish-gate.sh` matches the golden bytes. `publish-registries.sh` is the entry point: `publish-build.sh` (with `publish-inside.sh`, `publish-embedded.sh`, `publish-sign.sh` and `publish-check.py`) builds and checks every artifact, then `publish-upload.sh` (with `publish-query.sh` and `publish-published.py`) uploads; `publish-lib.sh` holds the target table, the credentials and `publish_container`, the one place that starts a golden-gate or build container (repo read-only, `docker-compose.publish.yml`). `publish-inside.sh` builds the TypeScript package (`npm ci --ignore-scripts && npm run build` in a copy, then `npm pack`) and `publish-check.py` refuses an npm tarball without `dist/index.js` and `dist/index.d.ts` or with `src/`; `publish-npm.test.sh` (sourced by `publish-gate.test.sh`; `bash publish-gate.test.sh --npm` runs only its checks) tests both. The cross-language ring has its own scripts: `ring-toolchains.sh` (toolchain versions), `ring-cxx.sh` (the `CXX` wrapper for the `gcc:16` image) and `ring-wiring.test.sh` (wiring check of `test.yml`); `cpp/embedded/lib.test.sh` tests the embedded harness. The versions of the tools the scripts install (`npm`, `twine`, `platformio`, `idf-component-manager`, `build`, `setuptools`, `pytest`) are in `tool-pins.txt`, read through `tool-pin.sh`. `PACKBIN_BUILD_ONLY=1` runs the build phase alone with no credential and no registry write; it still needs `python3` on the host, `gpg` for the Java bundle and `git` for the vcpkg and Arduino clones, and it marks its artifacts so the upload phase refuses them even after a failed run. A local script that uploads the same registries would be a second publisher.
