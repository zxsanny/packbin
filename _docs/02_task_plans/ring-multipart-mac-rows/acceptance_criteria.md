# Acceptance criteria: frame ring, MAC rows over a message in several parts

Figures marked HEAD were read from the ring run on HEAD 98d2202 in this loop (problem.md).

- AC-1: `ring-cases.txt` holds 11 new good `mac` rows, each confirmed by the reference on load, message field in pieces: `P.two` (4|20 bytes, the tag of the single-piece row `E4`), `P.first0` (`-|` then bytes), `P.mid0` (`a|-|b`), `P.last0` (`a|-`), `P.all0` (`-|-`, the tag of `msg0`), `P.split56` (120 bytes as 56|64), `P.split64` (65 bytes as 64|1), `P.bytes5` (five pieces of 1 byte), and `P.n8`, `P.n16`, `P.n32` (tag lengths 8 and 16 over three pieces; 32 over a 255-byte message in four pieces).
- AC-2: 2 new tampered `verify` rows with pieces: `P.v.bit` (one flipped bit in the tag) and `P.v.order` (a valid tag over `a|b` given with the pieces as `b|a`), each `invalid` by the reference; 2 new `refuse-mac` rows with pieces: `R.mac.p.nbad5` (`n` 5) and `R.mac.p.label0` (empty label), each `BadValue`.
- AC-3: the real ring (8 drivers built and started as `ring-frame.sh` does) on the new file prints `ring-frame: 30 mac rows and 11 refusal rows`, `ring-frame: 30 verify rows for each of 8 writers, and 7 refusal rows`, `pair <writer> -> <reader>: 56 rows, 0 mismatched` for 64 pairs (HEAD 45: 26 seal + 19 mac), `refusals <lang>: 76 rows, 0 mismatched` for 8 languages (HEAD 72: +2 verify, +2 refuse-mac), `ring-frame: 64 pairs, mismatched: 0`, exit 0.
- AC-4: all 8 drivers hand the package every piece of a `mac` / `verify` line as its own piece, in order, empty pieces included (no joining in the driver). A piece that is neither hex nor `-` (`ab|zz`), an empty piece spelled as nothing (`ab||cd`, `|ab`, `ab|`) is a malformed line in all 8 drivers: non-zero exit naming `frame line N`, no result for it. `ring-frame-drivers.test.sh` has the check for all 8 languages.
- AC-5: the new rows can fail. A stand-in driver that hands the reference only the first piece, or stops at the first empty piece, makes `ring-frame.test.sh` exit 1 naming `P.two` (first piece, as writer and as reader) and `P.mid0` (empty piece, as writer and as reader); with the real ring, a one-line mutation of one real driver (the Go driver passing only `parts[0]`) is red and names the rows, then removed. A driver that joins the pieces or drops an empty one gives the same tag (HMAC over the concatenation), so no row can tell it; the README says so.
- AC-6: the other row kinds and the 19 + 9 + 5 existing rows are unchanged: `git diff` of `ring-cases.txt` shows only added rows and the header comment; a single-piece line is written and read as before (the self-test's old cases pass unchanged).
- AC-7: `fixtures/frame/README.md` gives the field format (pieces joined by `|`, `-` for an empty piece, any other empty piece malformed) and the new row names; `ring_frame.py`'s docstring says the same.
- AC-8: no package source, wire format or version changes (`git diff --stat` touches only `scripts/frame`, `fixtures/frame`, `.github/workflows` and `_docs`).
