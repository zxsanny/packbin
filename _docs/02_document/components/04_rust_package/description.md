# Rust package

## 1. High-Level Overview

**Purpose**: Pack and unpack a caller-owned scheme for a native node.

**Architectural Pattern**: stateless clear pack, plus a session the caller holds.

**Upstream dependencies**: none inside the repo.

**Downstream consumers**: the caller's Rust program.

### Interface: Error correction (loop 38, ADR-007, `contracts/library/message-ecc.md`)

Optional parity bytes per scheme: `n` from 0 to 32, default 0, which keeps the bytes, the errors and the speed of an unprotected scheme. `n` is not on the wire. C++ is pending (AZ-2688).

| Name | Meaning |
|------|---------|
| `MapScheme::with_parity(n)`, `Scheme::with_parity(n)` | sets `n`; `with_limits` and `with_max_bytes` keep it. `n` above 32 panics, naming `n` and the limit. `parity()` reads it; `MAX_PARITY` is 32 |
| `unpack_repair(&MapScheme, bytes, limit)` | `Result<(Values, usize), UnpackError>`: the values and the bytes repaired; `unpack` is limit 0 |
| `BinaryPacker::unpack_with_repair(bytes, handlers, limit)` | `Result<usize, UnpackError>`, the bytes repaired, after the repair the type byte picks the handler; `unpack_with` is limit 0 and returns `()`. `DispatchHandler::parity()` is required (no default, loop 40: a hand-written handler of a scheme with parity bytes cannot leave it out) |
| `UnpackError::Uncorrectable` | more bytes wrong than `limit` allows; names no field |
| `UnpackError::TooLong { len, limit }` | a buffer above 254 bytes. A buffer shorter than `n` is `Short` naming the field `parity` |
| `UnpackError::BadLimit { limit, max }`, `MixedParity { first, other }`, `NoHandlers` | a limit above `n / 2` (also any limit above 0 with `n` = 0), handlers with different counts, and an empty handler list, all returned before any byte is read and before a session's receive index moves; the order is no handler, `DuplicateType`, `MixedParity`, `BadLimit` (`message-ecc.md`) |

- **Pack**: a clear message above `254 - n` bytes is `PackError::Type` naming the length and the limit (`SessionPackError::Pack` in a session).
- **Dispatch**: with one `n` the message is repaired first, then dispatched; a mix is `MixedParity`, a returned error and not a panic.
- **Session**: `PackSession::pack` pads, then appends the parity of the padded bytes. `PackSession::unpack_repair(bytes, handlers, limit)` repairs, drops the parity, removes the pad, then reads; `unpack` is limit 0. The receive index moves for every payload read from a valid handler set and limit, a refused one included. With `n` = 0 the payload has the length of clear pack.
- **`t` and detection**: `t` defaults to 0 and then any corruption of up to `n` wrong bytes is detected. A `t` above 0 repairs up to `t` wrong bytes but gives up detection: corruption of `t + 1` to `n - t` bytes is still refused, a larger corruption may be repaired to a different message. The contract table lists the chance (`n` = 4: 1 in 4.29e+09 at `t` = 0, 1 in 990,537 at `t` = 1, 1 in 485 at `t` = 2). `t` above `n / 2` is an error before any byte is read.
- **Size and speed**: a message is at most 254 bytes, parity included; pack refuses a clear message above `254 - n` bytes and writes nothing. Unpack of hostile bytes does at most about 3 x 255 x 32 field operations beyond the unprotected walk and never throws or traps on them. Acceptance bound EC-13 (a bound, not a recorded measurement): 1,000 unpacks with correction of a 254-byte message with 16 parity bytes and 8 wrong bytes in 1 second; 1,000 packs of such blocks in 1 second.

### Interface: nostd, the heap-free API (loops 50 to 53, epic AZ-2750, AZ-2749, AZ-2751 to AZ-2757)

`packbin::nostd` is a second API for firmware, in the crate beside the map API: plain-data schemes, caller buffers, errors as values. It builds with `#![no_std]` and no allocator when the crate is used with `default-features = false`. Owner decision B (2026-10-20): it follows the C++ core (`cpp/include/packbin/core.hpp`), because the map API is heap-bound by design (`Values` is a `HashMap<Rc<str>, Option<Value>>`, `pack` returns a `Vec`). The wire bytes are those of the map API.

- **Cargo features**: `std` (default, implies `alloc`; the map API, its sessions and error correction), `alloc` (`nostd::pack_vec`), and `text` (strings and dictionaries, AZ-2754), `ecc` (message error correction, AZ-2755), `session` (parts of `nostd`; `session` is the session pad, AZ-2756) and `frame` (frame mode of the session, AZ-3203). The map API always has the first three. With `text` off a scheme with `utf8`, `dict` or a list of strings is refused by `validate`; `utf8_wire` works in every build. With `ecc` off a scheme with parity above 0 is refused.
- **Scheme**: `Scheme::new(type_number, &[Field])`, a table in preorder (the C++ table shape): each entry's `span` counts it and its members. Kinds: the ten numbers (`u8(0)`, `be(i32(1))`, ...), `bytes(id, n)`, `boolean(id)` (a presence bit, only in `flags` or under a flag bit), `flags(id, entries)`, `flag_byte(number)` and `flag_bit(number, entries)` (split form), `when(id, source, value, entries)`, `sized(id, count)`, `bits(id, count)`, `packed(width, id, count, bias)`, `u2(id, n)`, `group(id, entries)`, `repeat(id, entries)`, `times(id, count, entries)`, `list(id, entries)`, and with `text` `utf8(id)` (decoded text), `dict(id, entries)` with its `key()` entry first; `utf8_wire(id)` keeps a string as it is on the wire (the payload after the count, in every build). Order ids follow the C++ rule (each field the next id; `flags`, `when`, `u2`, `group`, `repeat`, `times` the id of their first member; a flag byte and a flag bit none), except that a `list` takes the next id because the row finds its items by it (its element starts at 0). `Scheme::with_parity(n)` (0 to 32, needs `ecc` above 0), `Scheme::with_limits(max_rounds, max_slots)` (std defaults 65,535 and 1,048,576; the core counts rounds per container where it stands, not per field per call). `validate` refuses what the map API refuses at construction (order, scope, `when` value ranges, a bool source other than `true`, nine flag bits, bools outside `flags`, nested rounds, empty round bodies, list elements) plus table errors (spans, ids above 32,767, a widths or bias out of range), and `pack` and `unpack` call it first. References (`when` and count sources, flag bytes, late bits) are found by scanning the table where they are used, so the scheme stays plain `const` data.
- **Row**: the caller implements `Row` by field id: `num`, `bytes`, `set_num`, `set_bytes` (required), and with default bodies `flag`/`set_flag` (`boolean`), `clear` (called for every member before an unpack, so a skipped member reads as absent), `slots`/`set_count` (caller storage for `sized`, `bits`, `packed` and decoded strings; shorter storage is `TooMany`, for a string with the full text size in `needed`), a string is read through `bytes(id)` (UTF-8) on pack, a wire string through `bytes` and `set_bytes`, a `dict` item holds its key under `DICT_KEY` (`bytes`, `slots`, `set_count`) and its element under id 0, `count`/`item`/`item_mut` (the items of `repeat`, `times`, `list`, each a `&dyn Row`). In `flags`, under a flag bit and in a `when` body, a `None` leaves the member off the wire; elsewhere a missing value or one of another kind or length is `BadValue` naming the field.
- **Calls**: `pack(&scheme, &row, &mut out) -> Result<usize, Fault>`, `pack_with(.., &mut scratch)` (the compact text encoder keeps its parse in the caller's `[u32]`, `SCRATCH_WORDS_PER_CHAR` = 3 words per code point of the longest string that may shrink; a string that needs more is `ScratchTooSmall` with the words needed; `pack` passes none, so such a string fails there), `unpack(&scheme, bytes, &mut row)` and, with `ecc`, `unpack_repair(&scheme, &mut data, &mut row, limit) -> Result<Unpacked, Fault>` (repair in place up to `limit` wrong bytes, `limit` 0 to parity / 2, the count in `Unpacked::repaired`; `unpack` of a protected scheme only detects; `pack` appends the parity bytes and refuses fields above 254 minus the parity count with `TooLong`; `nostd::ecc` exposes the codec `protect`, `check`, `repair`, shared with the map API through `ecc_core.rs`) (the row is a `&dyn Row`, so one walk is linked whatever the row types); `Fault { error, offset, field, needed }` with the C++ error kinds (`ShortPacket`, `TrailingBytes`, `TypeMismatch`, `BufferFull`, `TooMany`, `BadValue`, `SchemeInvalid`, `ScratchTooSmall`, `Uncorrectable`, `TooLong`). A failed `unpack` may leave the fields read before the failure in the row.
- **Session** (`session`, AZ-2756, `nostd/session.rs`): `Session::load(seed)` (32 bytes), `start(nonce)` and `join(nonce)` (16 bytes the caller supplies; no randomness in the core), `pack`/`pack_with` (pack clear, pad in place with the next send position, then the parity over the padded bytes) and `unpack` (detect only) / `unpack_repair` (with `ecc`; repair, drop the parity, remove the pad, read; `data` ends as the clear packet). The hash, HKDF and pad are `rust/src/session_core/`, one copy that the `std` `PackSession` also runs, so the bytes are equal (cross-open tests). A bad seed or nonce size, a session not open or already open is `BadValue` (`needed` the size); a pack that fails leaves its written bytes zeroed and the send position unused; the receive position moves for every packet that reaches the pad, a refused one included, and for no refused argument. `Session` is not `Clone`. Nonce reuse under one seed is the caller's duty and not detectable. Device figures (loop 53): `session` 18,404 B flash and 1,832 B stack on the probe round trip, no limit yet.
- **Frame mode** (`frame`, AZ-3203, `nostd/frame/`; contract `pack-session.md` 2.0.0, ADR-008): a second mode of `Session`, opt-in like `session` (not implied by `std`; tested with `--features frame` and `--no-default-features --features frame`, which builds `#![no_std]` with none of the stream code). `Session::load_frame(key, epoch, FrameConfig { tag_len, directions })` (or `Session::frame_unloaded()` then `load_frame_in_place`, which derives the keys where the session lives and keeps a 600-byte copy off a small stack: the device probe uses it), `set_previous(key, epoch)` / `clear_previous` (used by open only), `seal_frame(direction, &MsgCtx, ad, clear, plain, out)` and `open_frame(direction, &MsgCtx, ad, body, clear_len, replay, out)` (replay window and counter optional per call; `Opened { slot, clear_len, plain_len }`), `MacKey::derive(key, epoch, label)` with `tag` over parts and a constant-time `verify`, and the caller-owned `ReplayWindow` (`check`, `commit`, `from_parts`, `parts`). New error kinds `TagMismatch`, `Duplicate`, `TooOld` join `Error` (same names in every package). The key schedule and the HMAC pad states are derived once at load (`session_core/hmac.rs`; the stream functions `pad::xor`, `split_keys` and `hkdf` are untouched, `pad::xor_with_nonce` is the frame ChaCha20); the tag compare folds every byte and passes the accumulator through `black_box`; the module forbids `unsafe`. Sizes (host, `size_of`): `ReplayWindow` 16 B, `MacKey` 68 B, a frame-only `Session` with two slots and three directions 588 B (704 B with `session` on too; target at most 640 B for the frame-only build). Tests: `tests/frame_vectors_tests.rs` (the shared fixture `fixtures/frame/vectors.txt`, public API, with and without `std`), `src/frame_core_tests.rs` (key rows, every single-bit flip of E1 to E3, replay before crypto with test-only SHA-256 and ChaCha20 counters, previous slot, MAC-only, cost of at most 4 blocks and 6 compressions) and `src/frame_hostile_tests.rs` (refusals with no partial output, random hostile bodies, a model of the window); a doc example on the module. Device figures (loop 69, Cortex-M4F `mps2-an386`, probe seals and opens E1 with a window and verifies E4): `frame` 19,772 B flash and 1,896 B stack (limits 20,480 B and 1,991 B); the four existing sets are unchanged to the byte (base 14,700 B / 456 B, text 26,632 B / 2,760 B, ecc 17,980 B / 760 B, session 18,404 B / 1,832 B, measured on the same host before and after), and a set without `session` must link no stream-session symbol (`stream_hits` in `checks.sh`).
- **Key wipes** (loop 73, AZ-3275; owner decision 2026-10-26): every wipe of key material goes through one helper, `session_core/wipe.rs` `wipe` (a `core::ptr::write_volatile` per element, then `compiler_fence(SeqCst)`; the crate's only `unsafe` block). The compiler may not remove a volatile write as a dead store, which `core::hint::black_box`, used before, did not promise. It clears: the HKDF temporaries on every way out of `hmac_sha256` and `derive` (the key-and-pad block, the inner digest, both hashers' state and block, `prk`, the last output block); the ChaCha20 `state` and `work` words after each block and the keystream block after each `xor` and `xor_with_nonce`; `split_keys`' 64-byte output; the HMAC pad blocks of `Pads::new` and the pad states on drop; the seed at `open` (wiped in place before the slot is emptied, std and heap-free) and on drop; the frame keys. Not cleared: copies the compiler makes when a value is moved or returned by value (`split_keys` and `hmac_sha256` results, `Pads::new`): Rust gives no way to reach them (L73-1); the SHA-256 round schedule and working words of `compress`, as in the platform hashes of C#, Java and Swift (owner); the per-message HMAC output and inner digest of `Pads::mac`, which hold no key words; the std `PackSession` keys until the memory is reused (no `Drop`, as in the managed stream sessions). The contract keeps "best effort". Device cost (loop 73): `session` +16 B flash, `frame` +152 B, stack -24 B each; the stream pad over 1 MiB in release, see the loop 73 batch report.
- **No panic path**: the module denies `unwrap`, `expect`, `panic`, indexing and unchecked arithmetic (clippy); `slice::reverse`, `copy_from_slice`, `split_at_mut` and every `chunks*` have panic paths at opt-level z and are not used (also in `ecc_core.rs` and `session_core/`). ## 5. Implementation Details

**State Management**: clear pack is stateless. A session keeps one send counter and one receive counter. A `FlagByte` handle holds only its name: `MapScheme::new` gives each flag-byte read a slot and numbers its bits by field order, so one handle can build any number of schemes. The typed `Scheme` names what it generates, `__flags_N` for a `flags` and `__bound_N` for a bound `list`, `dict` or `list_u16` (loop 13), from one counter that every `times` element shares with the row, so two unnamed containers, or one in a `times` element, never get the same name. Before, the container constructors hard-coded `__list` and `__dict`, and a second bound list overwrote the first.

**Error Handling Strategy**:

## 7. Caveats & Edge Cases

**Known limitations**:
- The first release has no code generator
- A `list` or `dict` element must be one integer, float, bytes, utf8, list or dict, or a `u2` with one name; any composite element panics at construction instead of losing data (loop 13). The typed API still binds only those: `list_u16` keeps an `element_id` argument that must be 0 (C18)
- The typed API has no flag-byte, `repeat` or `u2` form and no generic `list` or `dict` binder (C18); a split flag byte or a `repeat` is built with the map API (`MapScheme`, `pack`, `unpack`) or a raw `SchemeItem::Field`. A raw `SchemeItem::Field(repeat/when/flags ...)` in a typed scheme packs nothing and drops on unpack
- A `when`, `times` or `repeat` as a `flags` member, as a flag-bit field, or in a group under them is written since loop 18 (AZ-2120, AZ-2128; `member_on`, `when_on`, `times_on` and `repeat_on` in `walk/flag_bits.rs`; map API and the typed `Scheme<T>` forms that can hold them; see Flag group presence). Left as decided: a `when` with a false condition drops a given body silently, and a `times` whose count field was skipped is refused when values are given in the combined `flags` form (since loop 20, AZ-2360, as in the other five packages) (a `repeat` whose rounds are all empty `{}` has no value and its bit stays clear; a mix of empty and filled rounds fails pack). A split flag byte decides its `when` or `times` bit where the byte is read; since loop 19 (AZ-2331) pack fails when that leaves the bit clear while the body would be written (see Split bit with a dropped body). Sibling members of one `flags` are separate flag-byte scopes since loop 19 (AZ-2333, as in C++, TypeScript and Java; see Sibling `flags` scope)
- Rust has no bool value: a bool is the integer 0 (clear) or 1 (set), so a `when` on a bool is an `eq` with 1, and any other value panics when the scheme is built (`when at id 1 ... "on"`). A map `times` gives a lone scalar to every round, since loop 18 (AZ-2311; `slice_times`: `u8 "0"; times(1, "0", [u8 "1", u8 "2"])` with `"0"` = 2, `"1"` = 1 and `"2"` = [4, 5] packs `010201040105`); a lone dictionary for a `dict` name in a round is `PackError::Type` naming the member (AZ-2308; it packed one round for a count of 1 and failed with `Missing` for 2). Pack caps a `times` count at the scheme's `max_rounds` since loop 19 (AZ-2329, see Pack round cap): a `u32::MAX` count with a lone value wrote about 4 GiB before. A `repeat` is not capped and `max_slots` is not applied on pack
- Map API: a hand-built `times` fed per-name lists only (no `"__times_<anchor>"` key) slices direct children only (`slice_times`), so a non-empty list or a single value kept under a member below a `flags`, `when` or a group below them is refused with a `PackError::Type` naming it (AZ-2189; since loop 22 a list under a `flags` or a flag bit is read one item per round, AZ-2414, and only a member under a `when` is still refused); an empty list still packs. A list longer than the count is refused with a `PackError::Type` before any round is written (`{"0": 2, "1": [1, 2, 3]}`: `times at id 1: '1' has 3 items, count is 2`; `check_longer` in `walk/times.rs`, loop 16, AZ-2237), as TypeScript, Python, Java and C# do; it checks the data members of the round (a direct field or the field of a flag bit), not the names of a `flags`, a flag byte or a `group`, and a longer list is reported before any item error. A `times` inside a `repeat` round stays allowed, where Java, C# and TypeScript refuse it (AZ-2127). A map scheme that reuses one member name in two `times` cannot repack unedited values (it fails loudly)
- A data name equal to a `flag_byte` or `flags` byte name builds, and one value replaces the other in the unpacked values (`u8("m"), m.byte(), m.bit(u8("a"))`: `01070105` unpacks to `m = 1`, the 7 is lost, and repacks as `01010105`); `check_names` does not cover byte names, and a flag-byte handle read twice must stay legal (AZ-2247, open, a follow-up ticket)
- Two declarations inside one `when` body build (`s = 8` for `01010708`), as in TypeScript, Python and Java (AZ-2247, open)
- Two typed `BoundField`s with different ids that read and write the same struct member build and pack the value twice; Rust cannot see inside the closures. In the typed `Scheme<T>` a name is the field id, which `check_order` already keeps unique, so `check_names` reaches the typed form only through a raw `SchemeItem::Field` (AZ-2247, open)
- `u8("x"), repeat(1, [u8("x")])` round-trips (`01050607` repacks to itself) and is refused all the same, for equality with the other packages; making `Repeat` its own scope in `names.rs` would allow it again (one line; the owner chose refusal, AZ-2247)
- A multi-name `u2` in a map `times` fed per-name lists is not sliced past its first slot (`slice_times`, `check_longer`): it fails with `PackError::Missing("2")`, as before loop 16 (open)
- Pack records each field it writes in a per-scope map (`Written` in `walk/written.rs`, moved out of `walk/pack.rs` in loop 18), so a flat scheme packs about 1.5 times slower in release than before (12 `u8` fields, 300k packs: 89 ms, now 140 ms; a 60k-element list, 1.0 times). Skipping the record for a scheme with no `when` or count would remove it; not done (open, Low)
- Typed `times`: `PackSession::pack` of a row whose count and `Vec` length differ returns `Err(SessionPackError::Pack(PackError::Type(..)))` (AZ-2105). Unpack keeps one `Values` per round, about 300 to 500 MB of peak memory for 1 MB of one-byte rounds without a limit (the count is never pre-allocated); capped by the round limits since loop 15

**Hostile input** (loop 11). Unpack of untrusted bytes returns an error value and no row, within a time bound set by the input length and, for rounds, a memory bound set by the scheme's round limits (below). It does not throw and does not loop on input it cannot consume. The cases:
- a `repeat` round that reads 0 bytes ends the repeat; the bytes left come back as trailing bytes
- a `times` round, or a `list` or `dict` element, that reads 0 bytes is an error, even for a small count (a few bytes could otherwise ask for 65 535 empty items)
- a negative count, a count larger than the bytes left, invalid UTF-8 in a string or a dictionary key, and a count whose source field is absent (it sat behind a clear flag bit)

The error shape is interim: a short-packet-style value. Its kind, label, `needed` and `left` are decided under C15, so no new public error type was added. In Rust it is `UnpackError::Short` with `needed` 0. A zero-width `times` round is labelled `"times"`; the `repeat` case is `UnpackError::Trailing`. A `packed` count goes through checked arithmetic (`packed_layout` in `walk/cursor.rs`), so a count of 2^63 or more, or one that overflows a 32-bit `usize`, is an error, not a wrap. `walk/element.rs` reads one `list` or `dict` element and rejects a zero-width one.

**Construction rules** (`field/order.rs` for ids and scope, then `check_shape` in `field/shape.rs` for flag bits, bools and rounds, then `check_integrity` in `field/integrity.rs` for `when` and elements, then `check_names` in `field/names.rs` for a data name declared twice (AZ-2247); `MapScheme::new` runs all four, also for the typed `Scheme::new`):
- a `when`, a `sized`, `bits`, `packed` or `times` count, or a flag bit may only name an id inside its own `repeat` or `times` body, because each round reads into its own values
- a `when` or a count (`sized`, `bits`, `packed`, `times`) must also name a field that its own scope declared earlier, by name as well as by numeric id (`declared_integer` in `field/integrity.rs`, loop 16, AZ-2117): a name outside the body, inside an earlier `repeat`, `times`, `list` or `dict` body, declared later or never declared is refused, and so is a numeric id whose slot carries a non-numeric name (it never matched). The panic names the owner and the field: `when at id 2 names field "1", which is not in the same scope (...)`, `times at id 2 names field ...`, `the count of "2" names field ...`
- a split-form flag bit binds to the latest read of its flag byte that it can see, earlier in the same scope; a flag byte read inside a `when`, a `flags` member or a flag bit is not visible after it, and one outside a `repeat`, `times`, `list` or `dict` body is not visible inside
- a bit's position is its order among the bits of that read, not the order of `bit()` calls; a second read of the same flag byte starts its own bits (as C++)
- one `flags` holds at most 8 members and one flag-byte read at most 8 bits (a bit inside a `when` counts against the same read); the 9th panics naming that field
- a bool (an empty `group`, typed `BoundField::bool_flag`) stands only directly inside `flags` or under a flag bit; at the top level, inside `when`, `repeat`, `times`, a plain group (also one under `flags`) or as a `list` or `dict` element it panics naming its id
- no `repeat` inside a `repeat` or `times` round and no `times` inside a `times` round, at any depth (also through `when`, `group`, `flags` or a flag bit); a `times` inside a `repeat` round stays allowed, and a `list` or `dict` element starts outside any round
- a `when` tests an integer or bool field (an empty group counts) against an integer `eq` value; a float, bytes, utf8, `sized`, `bits`, `packed`, `list` or `dict` source, or a float, text or other non-integer `eq`, panics naming the `when` (a `when` on a utf8, bytes or f32 source with a same-type `eq` built before). The check applies to a tested name that scope declared before the `when`. Since loop 18 (AZ-2126) a bool source accepts `eq` with 1 only (`eq(bool, 0)` and any other value panic, naming the `when` and the field), and a count (`sized`, `bits`, `packed`, `times`) that names a bool or another non-integer field panics (`the count of "s" names field "on", which is not an integer`); a count may still name a `flags` byte or a flag-byte name, which are integers
- a `list` or `dict` element is one integer, float, bytes, utf8, list or dict, or a `u2` with one name; the walker keeps one value per element, so a group, flags, `when`, `repeat`, `times`, flag byte or bit, `sized`, `bits`, `packed` or a `u2` with several names would lose values, and panics naming the owner and the element

**Round limits** (loop 15, AZ-2219; `field/map_scheme.rs`, `scheme/mod.rs`, `walk/cursor.rs`; the `Cursor` moved out of `walk/unpack.rs` in loop 19, AZ-2342). A scheme carries `max_rounds` (default `DEFAULT_MAX_ROUNDS`, 65,535, exported at the crate root) and `max_slots` (default `DEFAULT_MAX_SLOTS`, 1,048,576 since loop 22, 4,194,304 before). `MapScheme::with_limits(self, max_rounds, max_slots)` and `Scheme<T>::with_limits` (which delegates to its layout) take the scheme and return it with the new limits (clone first to keep the original); `max_rounds()` and `max_slots()` read them. A zero limit panics naming it, unlike the typed errors of C#, TypeScript and Java; `usize::MAX` is valid and lifts the default. `repeat` and `times` store `slots`, the count of the names a round can hold (`round_width` in `field/map_scheme.rs` since loop 21, AZ-2382: distinct names, an empty group's name included, a non-empty group's, `flags` and flag-byte names not), computed once at construction. The per-call `Cursor` carries the limits and a slot counter, and `start_round(field, started, slots)` runs as each round starts, before its `Values` is built. The round that would be the 65,536th of one field, or would take the slot total past `max_slots`, returns `UnpackError::Short` with the field `"repeat"` or `"times"` and `needed` 0; no new error variant. Rounds of a `times` inside a `repeat` count their own `max_rounds` afresh per walk and add to the shared slot total. A typed `Scheme` refuses the same way and its handler is not called. A `times` count is not refused up front.

**Bool** (loop 12): the bit is set only for true (typed `Some(true)`, map value `1`); `0` or no value leaves it clear, and a map value other than 0 or 1 fails pack with `PackError::Type`. A set bit unpacks as `Value::U8(1)` (typed `Some(true)`), under `flags` and under a flag-byte bit alike; a clear one is absent (`None`).

**Flag group presence** (loop 16, AZ-2128; `group_on`, `any_member_on` and `member_on` in `walk/flag_bits.rs`, which also holds `collect_flag_bits`, moved out of `walk/pack.rs` in AZ-2237). A group under `flags` or a flag bit is on when its own name has a value, or any value inside it, at any depth, is present: an integer, float, bytes, utf8, list, dict, `sized`, `bits`, `packed`, a `u2` name, a nested group or a nested `flags` (its own name or any member). A flag byte inside is skipped (its value comes from its bits), and since loop 18 a `when` (its condition holds on `wrote` and its body has a value), a `times` (its count is above 0; a skipped count is no round) and a `repeat` (at least one round has a value) count as members; `u8 "0"; flags(when(eq("0", 1), [u8 "1"]), u16 "2")` with `"0"` = 1, `"1"` = 7 and `"2"` = 90 packs `010103075a00` (it packed `0101025a00`). A group whose bit is on is written in full, so a required value that is missing fails pack with `PackError::Missing` naming it.

**Written values** (loop 16, AZ-2237; `walk/pack.rs`, `Written` in `walk/written.rs` since loop 18). Pack decides every `when` and takes every count from what it wrote in the same scope, as unpack does from what it read (map form and typed `Scheme<T>`). `Written` holds the fields written in one scope (the top level, one round of a `repeat` or `times`, one `list` or `dict` element; a list or dict element uses `Written::unread()`, which stores nothing, because elements cannot hold a `when` or count). A field behind an untaken `when` or a clear bit is not written, so a `when` on it does not match and a count that names it returns `PackError::Missing` naming the count's field. A `flags` byte or flag byte is recorded as the byte pack wrote, and a set bool as `1`, so a `when` or count that names one does not read a value kept in the row. A `times` leaves one list under each name its rounds wrote in the scope around it (`RoundLists`; a name written twice in one round keeps the later value, as unpack builds it), so a `when` or count on such a name finds a list; a `repeat` does not. A map `times` without rounds checks first that no list is longer than the count (`check_longer` in `walk/times.rs`).

**Session pack** (loop 16, AZ-2105; `session/mod.rs`). `SessionPackError { NotOpen, Pack(PackError) }` is exported at the crate root. `PackSession::pack` returns `Err(NotOpen)` before `start` or `join` and `Err(Pack(e))` with the error of `BinaryPacker::pack`, and the send counter moves only when the pack succeeds, so a failed pack leaves the next payload readable by the waiter.

**Checked count** (loop 16, AZ-2118; `borrowed_count` in `walk/pack.rs`). The count of a `packed` field or a `times` goes through `i64::try_from` and `checked_add`: a count that does not fit (2^63 or more) or whose bias overflows returns `PackError::Type("<label>: item count out of range")` in debug and release; a negative result keeps `<label>: item count N`.

**Typed `times`** (loop 13, `scheme/times.rs`). `SchemeItem::times(anchor, count_id, get, set, members)` binds a `Vec<E>` with `E: Default + 'static`: `get` lends `&[E]`, `set` takes the `Vec<E>`, and `members` are items on `E`, numbered from `anchor` on like the items of a `when`. A reference among them names an id of the same element. It replaces the three-argument form and the `SchemeItem::Times` struct variant. The element items compile lazily, inside `Scheme::new`, with the scheme's name counter, so an element panic fires there and no element reuses a generated name. The rounds travel as `Value::Groups` under `"__times_<anchor>"`, built by `read_values` and read back by `build_row` in `scheme/mod.rs`. Pack fails with `PackError::Type` (`times at id N: count C, R rounds`) when the count differs from the `Vec` length. Unpack makes one `E::default()` per round and sets the `Vec`, also for count 0 (it replaces a non-empty default). A `times` inside a `times` element is refused at construction. The README times and route vectors pack the same bytes as the other five packages.

**Integer `when`** (loop 13, `value.rs`). `when_matches` takes the members when `eq` and the source are integers of the same number, whatever their width or sign, so `Value::U16(1)` matches a `u8` source and a `u64` above `i64::MAX` matches by value. It replaced `values_eq`, which was true only for the same variant, so such a `when` never fired and dropped its group without an error. `same_value` (floats by bits, so NaN equals itself) compares the rounds with the lists beside them.

**Map `pack` / `unpack`** (public since loop 12, `walk/mod.rs`): values are keyed by field name. A `flags` byte or flag byte is computed from its fields on pack and returned under its own name on unpack as `Value::U8` of the byte read. `repeat` rounds are `Value::Groups` under `"__repeat__"` (no value packs no rounds). A `times` unpacks to one `Value::List` per name (an item for every round that read it) and also to its rounds as `Value::Groups` under `"__times_<anchor>"`, one `Values` per round, always present and empty for count 0 (`walk/times.rs`, `times_name` in `field/mod.rs`). Pack takes the Groups when the key is there: as many as the count, else `PackError::Type`, and a member under `flags`, `when` or a group stays in its round. Without the key each direct field takes a `Value::List` with one item per round (`slice_times`), and a non-empty list or a single value kept under a member below a `flags` or `when` is a `PackError::Type` naming it and the `"__times_<anchor>"` key to use (`check_aligned` in `walk/times.rs`, loop 16, AZ-2189; an empty list still packs, because it holds nothing to drop); a list longer than the count is a `PackError::Type` too (`check_longer`, AZ-2237, see §7). With both, a value kept for a name of the rounds (a non-list counts as a list of one item) must equal what the rounds hold, else `PackError::Type` (`times at id N: list for 'x' disagrees with its rounds`). To change a value after `unpack`, edit the rounds and drop or rewrite the lists, or edit the lists and drop the `"__times_<anchor>"` key (not for a member below a `flags` or `when`: edit its rounds); leaving both and changing one is an error. A flag bit inside a `when` that is not taken still sets its bit on pack; unpack checks the `when` first and never reads the field (`bitwhen` vector: `{k:0, v:5}` packs `010001`, `{k:1, v:5}` packs `01010105`).

**Pack round cap** (loop 19, AZ-2329; `check_round_cap` in `walk/times.rs`, `max_rounds` threaded through `pack_fields`, `pack_one` and `pack_round` in `walk/pack.rs`). In the `times` arm of `pack_one`, a count above the scheme's `max_rounds` returns `PackError::Type` (`times at id 1: count 65536 (from '0') is over the 65535 rounds a scheme allows; members 'pt'`) before any round is sliced or written. It covers `__times_N` groups, a `times` in `flags` and in a round, and a count of 4 000 000 000; `max_slots` and `max_bytes` are applied on pack since loop 20 (see Pack output budget). A scheme built with `with_limits(2, ..)` cannot pack a count of 3; 65 535 is the boundary that packs. Tests: `pack_round_cap_tests.rs`.

**Split bit with a dropped body** (loop 19, AZ-2331; `check_split_bit` in `walk/flag_bits.rs`, called for each bit in the `FlagByte` arm of `pack_one`). A split flag byte decides its bits where it is written. For a `when` under a bit whose source is written after the byte, the value given for the source decides: if it matches and a body value is given, pack returns `PackError::Type` naming the body (`'speed' is given, but its when on 'mode' holds, or is written after the flag byte, so the body would be written but the byte leaves its bit clear; write 'mode' before the flag byte`); a false condition packs silently, before or after the byte (literal AC-3), and a source that is never written and has no value is silent (review A2). For a `times` whose count is not written where the byte is written, a given `__times_N` rounds list or a body value is refused (`'pt' is given, but its times count 'n' is not written where the flag byte is written ...`). The combined `flags` form is unchanged. `u8 mode; flagbyte m; bit m {when(mode == 1, u8 speed)}; bit m {u16 heading}` with `mode` = 0, `speed` = 7 and `heading` = 90 packs `0100025a00`. Tests: `split_form_loud_tests.rs` (one older test, `ac3_split_form_when_false_...`, rewritten).

**Sibling `flags` scope** (loop 19, AZ-2333; `shape_one` in `field/shape.rs`). Each member of one `flags` is a part of its own for flag-byte binding (`flags.conditional(|f| shape_one(member, ..))`): a flag byte read inside one member is not seen by a bit in the next, as in C++, TypeScript and Java. A scheme whose bit bound to an earlier sibling's byte binds to the outer byte now, or is refused at construction when there is none. Reference (TypeScript run, scheme S1 `flagbyte fb; flags{group g1 {v; fb byte; bit fb x}, group g2 {bit fb y}}; bit fb b`): `v` = 3, `x` = 5, `y` = 6, `b` = 7 packed `0101030303050607` and now packs `0103030301050607`. Tests: `flags_member_scope_tests.rs`.

**Eq range** (loop 19, AZ-2338; `Source::Integer(low, high)` and `check_when` in `field/integrity.rs`). Each integer source carries its range (`int_source`; a flag byte and a `flags` byte 0..255, a `u2` slot 0..3); a `when` whose `eq` number is outside it panics when the scheme is built (`when at id 2 compares field "0" with 300, which is outside the 0 to 255 that field holds, so the comparison could never match`). A `Value::U16(300)` against a `u8` field, `Value::U64(u64::MAX)` against an `i64` field and `Value::I8(-1)` against a `u64` field are refused. Rust has no bool `Value`, and an `eq` that is not an integer was already refused. Tests: `eq_range_tests.rs`; two `eq` tests changed (`eq(i8, U8(255))`, `eq(u64, I64(-1))`).

**Lone buffers and count 0** (loop 19, AZ-2332, AZ-2335; `holds_bytes` and `slice_times` in `walk/times.rs`). A lone `Value::Bytes` for a `bytes` or `sized` name in a `times` round is refused (also for a count of 1); `repeat` takes its rounds explicitly, so nothing is refused there. A `utf8` lone string still goes to every round. A `times` count of 0 with rounds or a list of values is `PackError::Type`; a lone scalar with count 0 packs `0100`. Tests: `lone_bytes_in_round_tests.rs`, `times_count_zero_tests.rs`.

**Pack output budget** (loop 20, AZ-2354, AZ-2355; `walk/pack_out.rs`, `walk/pack.rs`, `walk/times.rs`, `field/map_scheme.rs`, `scheme/mod.rs`). A `MapScheme` carries `max_bytes` (default `DEFAULT_MAX_BYTES`, 16 777 216, type byte included, exported at the crate root), set by `with_max_bytes` on `MapScheme` and the typed `Scheme` (0 panics; `usize::MAX` is valid); `with_limits(max_rounds, max_slots)` keeps it. `pack_out.rs` (200 lines, new) holds the output buffer: every write calls a reserve that returns `PackError::Type` `s: the packet would be 16777477 bytes, above the limit of 16777216 bytes` before anything is written or allocated for it, and the buffer grows by doubling but never past `max_bytes`. Slots are charged as each round starts with the width Rust's own unpack charges (`round_width`, the one rule of the six packages since loop 21), one counter per pack call, before the round's bytes: `k: the rounds would hold 1048580 slots, above the limit of 1048576 slots`. A `repeat` list above `max_rounds` is refused before any round, naming the first member whose list passes it (`k: the repeat count is 65536, above the limit of 65535 rounds`, in `times.rs`). The `times` cap keeps its loop 19 text. AC-1: 2.19 s and 5.5 GB before; the first message above in 4 ms and 35.5 MB RSS after. Reference rows 2, 3, 22 and 23 and the element row of `repeat` do not apply: Rust has no `times` or `repeat` in a `list` element. The AC-4 rows take about 20 s in a debug build (0.8 s in release). Tests: `pack_output_budget_tests.rs`, `pack_repeat_cap_tests.rs`.

**Combined `flags` skipped count** (loop 20, AZ-2356, AZ-2360 and review A4; `Form { Combined, Split }` in `walk/flag_bits.rs`). A `times` whose count was not written and that is given values is refused in both forms, naming the member (`pt: a value is given, but the count of its times is not written, so its bit is clear; write the count before the times`). `zero_given`, a count of 0 given in the row and written after the byte, applies to `Form::Split` only: it starts no round, packs a lone scalar as `01 00 00` and refuses a list (this was a real fix; the lone scalar was refused). The combined form refuses a skipped count with a stale `n: 0`, as TypeScript and C# do. A `when` decided by a split bit whose source is absent stays silent (owner decision, loop 20). Tests: `loop20_parity_pins_tests.rs` (also the enum pin: a Rust enum is not a value, the caller casts `Level::High as u8`).

**Source layout** (loop 19, AZ-2342; no behavior change, 479 tests before and after): `walk/cursor.rs` (121 lines: `Cursor`, `read_int`, `read_float`, `packed_layout`) was split out of `walk/unpack.rs` (471 to 352 lines), and `field/leaf.rs` (157 lines: the leaf field constructors `u8` to `packed`, `int_width`, `float_width`) out of `field/mod.rs` (479 to 332).

**Breaking changes for callers** (pack output is unchanged):
- A flag byte read in one `when` with its bit in another `when` worked before. It is now refused at construction.
- A flag byte outside a `list`, `repeat` or `times` body with its bit inside that body is refused at construction.
- A `times`, `list` or `dict` element that reads nothing is now an error instead of an empty item.

**Breaking changes in loop 12** (bytes of valid schemes are unchanged except where noted):
- A `FlagByte` handle no longer counts bits across schemes, and a second read of a flag byte no longer shares the first read's bits. A handle reused for a second scheme used to shift that scheme's bits.
- A map bool value `0` now leaves its bit clear (it set it before); a bool value other than 0 or 1, or a `"__repeat__"` value that is not `Value::Groups` (before: no rounds), fails pack with `PackError::Type`.
- A bool or empty group outside `flags` or a flag bit (it packed nothing and came back missing), a 9th `flags` member or flag-byte bit (a shift panic in debug, an aliased bit in release), a `repeat` inside a `repeat` or `times` round and a `times` inside a `times` round now fail at construction.
- A bool under a flag-byte bit now unpacks as set (it was missing).

**Breaking changes in loop 13** (wire bytes of valid schemes are unchanged):
- `SchemeItem::times` has a new signature (above) and the `SchemeItem::Times` struct variant is gone. The old form shipped in `v0.2.1` and never worked past a count of 1. Its construction panics moved from the call to `Scheme::new`.
- A `when` on a utf8, bytes, f32 or other non-integer source, or with a non-integer `eq`, now panics at construction. A list or dict whose element is a group, flags, `when`, `repeat`, `times`, flag byte or bit, `sized`, `bits`, `packed` or a multi-name `u2` now panics at construction (it lost values or failed at run time).
- A `when` matches by integer value at any width (it needed the same variant); two or more bound lists, dicts or `list_u16` fields keep their own members (they overwrote each other).
- Map `unpack` of a `times` also returns `"__times_<anchor>"` Groups, and map `pack` with both the Groups and a list that disagrees fails with `PackError::Type`. Before, the lists were the only form.
- Unpack keeps one `Values` per `times` round, about eight times the memory it used (312 MB peak for 1 MB of one-byte rounds, 37 MB before).

**Breaking changes in loop 15** (AZ-2219; wire bytes and the result for a packet within the limits are unchanged):
- Unpack of a map scheme or a typed scheme refuses a packet whose `repeat` or `times` starts more than 65,535 rounds, or whose rounds hold more than 1,048,576 slots together (4,194,304 before loop 22), until the scheme raises the limits with `with_limits`. A refused 1 MiB packet peaks at 20 to 57 MB, against 0.3 to 1.2 GB before.

**Breaking changes in loop 16** (wire bytes of valid schemes and rows that packed before are unchanged except where noted):
- `PackSession::pack` returns `Result<Vec<u8>, SessionPackError>` instead of `Option<Vec<u8>>`; code that matched `Some` and `None` does not compile.
