# Blackbox Tests 19: Loop 26 Swift package, the eighth language (FT-X-124 to FT-X-155)

Part of the blackbox set; the index is [blackbox-tests.md](blackbox-tests.md). Loop 26 (`swift-package`, AZ-2223; AZ-2513 to AZ-2524, 12 specs, 47 points) added `swift/` (library target `Packbin`, manifest `Package.swift` at the repository root): a hand-written Swift package with the bytes of the other seven for every shared feature, a Swift driver in the language-pair ring, a `swift` service in the CI suite, the Swift golden gate and a consumer resolve check of the existing `vX.Y.Z` tag (ADR-005; no Swift tag). Sources: `_docs/02_task_plans/swift-package/` (`problem.md` S-1 to S-5, `acceptance_criteria.md` SW-1 to SW-16, `scenarios.md` S1 to S12 and the assessment rows O1 to O3, `parity_differences.md`), the specs in `_docs/02_tasks/done/` (AZ-2513 to AZ-2524), `_docs/03_implementation/batch_01..10_loop26_report.md`, `implementation_completeness_loop26_report.md`, `test_run_loop26_report.md`, `_docs/loops/loop26/{review26,assessment26}.md`, [ADR-005](../adr/005_swift-installs-from-the-version-tag.md).

One table row per scenario, as in file 17. Swift test names are the real `@Test` function names in `swift/Tests/PackbinTests/*.swift` (swift-testing), written `Suite.function`; a parameterized test is named once. Every name below was checked against the test sources.

**Where it runs.** Swift 6.3.3 is installed on the owner's Mac: `swift test` at the repository root, with the Command Line Tools flags of `_docs/AGENT_GOTCHAS.md` (`-F` and rpath for `Testing`). The Linux run is the `swift:6.3.3` container: `docker compose -f docker-compose.test.yml run --rm swift` runs `.github/workflows/run-suite.sh swift` (resolve, strict release build with `-warnings-as-errors` and `-strict-concurrency=complete`, the debug tests, `swift test list`, the 60 s fuzz run, the thread-sanitizer run, the release speed run with the 1 MiB hostile unpack, the dependency check; it fails without `Package.swift` or `swift/`). The ring builds the Swift drivers with `.github/workflows/ring-swift.sh` (the runner's `swift`, else the `swift:${RING_SWIFT}` image).

**Step 11 (one total run, `scripts/loop-tests.sh`).** The Swift suite is 335 tests in 55 suites. On the Mac `swift test`: 335 pass. In the `swift:6.3.3` Linux container the `swift` stage passed (620 s: debug tests, a 60 s fuzz run, the thread-sanitizer run, the release speed run, the dependency check). The ring passed, the Go-Swift hand-offs included. The scaffold stage passed. The full publish gate passed in 1837 s (vcpkg checks NOT RUN: no vcpkg tool, as before). The other seven language suites passed (C++ on its serial retry after a build-directory race under load: first failure in a log, 24 s alone). Found only by the container run and fixed in the loop: the `swift:6` image tag does not exist on Docker Hub (it is `swift:6.3.3`); `stderr` in the Linux drivers is rejected by Swift 6; the thread sanitizer made the single-threaded size and speed tests take 25 minutes and fail their 1 s bounds (they no longer run, or assert the bound, under the sanitizer); the `NSDictionary` NFC/NFD test was flaky on Linux because Foundation merges the keys per process. Report: `_docs/03_implementation/test_run_loop26_report.md`.

**Toolchain.** The minimum is Swift 6.0 (`swift-tools-version: 6.0`, Swift 6 language mode; owner decision 2026-10-14, S-4 as amended); Swift 6.0 itself was not run, the CI image and the Mac compiler are 6.3.3.

**Status words.** Covered: a test or script ran green in loop 26 (on the Mac, in the container, or both, as the row says). NOT RUN: written, not executed in loop 26. BLOCKED: cannot run before a decision or an event (a push to Actions, a tag). FT-X-151 to FT-X-155 are the NOT RUN and BLOCKED items.
