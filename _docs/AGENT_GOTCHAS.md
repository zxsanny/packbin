# Agent gotchas

Session-start don’ts. One line each. Under one page. Do not duplicate `_docs/LESSONS.md`.

## Gotchas

- The auditor's fuzz corpora, per-language drivers, `cmp.py` and amplification probes live in a session scratchpad. Commit them under `fixtures/hostile/fuzz/` or the next unpack-changing loop rebuilds them from an old temp dir (recommended in loop 11, ignored, repeated in loop 13).
- On this arm64 Mac a green run needs these host recipes (loop 19: the ring and the publish gate also need `python3` 3.10 or newer, Apple's is 3.9: put a dir with `python3 -> /opt/homebrew/bin/python3.14` first on `PATH`, and give `publish-gate.test.sh` the same `PACKBIN_CXX_SYSROOT`) written nowhere else (repeated from loop 13, tripped again in loop 14): `PACKBIN_CXX_SYSROOT="$(xcrun --show-sdk-path)"` for `language-pair.sh` (else `'cstddef' file not found`); `typescript/node_modules/.bin/tsc --noEmit --strict --target es2022 --module nodenext --moduleResolution nodenext --allowImportingTsExtensions typescript/src/index.ts` for the strict check; and the Pico example needs a `--platform linux/amd64` container with its own cache under `.cache/embedded/amd64` (PlatformIO has no linux arm64 build of `toolchain-gccarmnoneeabi ~1.90201.0`; the ESP stage of `cpp/embedded/run.sh` shows `cpp-example-pico` failed on this host by design).
- `publish-vcpkg.test.sh` honors `PACKBIN_CXX_SYSROOT` for its cmake builds and the vcpkg consumer (it writes a temp overlay triplet); no extra recipe. Without a vcpkg tool it prints NOT RUN, which is not a pass.
- A worker in the shared tree never runs `git stash`, `git checkout`, `git reset` or `git clean`: in loop 15 the AZ-2214 worker stashed and popped once for a shellcheck baseline while three other workers were writing (the tree survived, by luck). Use `git worktree` or a tree copy under the scratchpad for baselines.
- `publish-position.sh typescript` without `typescript/node_modules` runs `npm ci` after a `cd`, because `npm ci --prefix` refuses the lock file (`Missing: ... from lock file`) when the path holds a symlink, and macOS temp dirs always do; `publish-position.test.sh` guards it with a symlinked temp path.
- A worker or reviewer command must end on its own: stdin from `/dev/null`, no bare `cat` or `read`, no unfinished here-doc, and a timeout on anything that can hang (macOS has no `timeout`: `perl -e 'alarm N; exec @ARGV' -- cmd`); in loop 16 a bare `cat` sat 2.5 hours and showed as a running task.
- A worker prompt forbids every index write, not only `git stash`, `checkout`, `reset` and `clean`: in loop 17 a worker ran `git rm --cached` on a deleted file (it undid it); say "no `git add`, `git rm`, `git mv`, `git restore --staged`" and check `git diff --cached` after each stage.
- `dotnet test csharp` without `MSBUILDDISABLENODEREUSE=1` hangs forever on this Mac at 646 of 649 tests: `SchemeTests.CompileFailRequiresScheme` starts a child `dotnet build` that deadlocks with MSBuild node reuse (loop 18, a worker lost 15 minutes). Always run `env MSBUILDDISABLENODEREUSE=1 dotnet test csharp --nologo`, as `run-suite.sh` does; put the variable in every C# worker prompt.
- C++ is built with `-Wall -Wextra -Werror` by GCC 16 in CI (`gcc:16`) and by Apple clang on this Mac: a clean `make -C cpp test` on the Mac proves nothing about GCC (loop 18: new test files failed the CI container on `-Warray-bounds` false positives and `-Wformat-truncation`). A C++ worker or the parent checks with `docker run --rm -v "$PWD":/src -w /src/cpp gcc:16 make test` (about 15 s) before the batch commit.
- The Cortex-M4F flash budget (8192 B) has a **32 B margin** after loop 20 (8160 B; the stack 448 of 512 B): any edit to `cpp/src/core` or `cpp/include` needs a flash saving first, or it goes to the next loop.
- The Cortex-M4F stack budget (512 B, `cpp/embedded/lib.sh`) has a 64 B margin (loop 18 was 56 B): GCC inlining `unpack_items` into `unpack_one` cost 64 B in loop 18. Any edit to `cpp/src/core/unpack.cpp` or `pack.cpp` runs the arm embedded stage (`docker compose -f docker-compose.test.yml run --rm cpp-embedded`, about 3 minutes) before the commit.
- `cpp/build/` is shared by the host `make` (Mach-O) and the `gcc:16` container (ELF): a binary built by one cannot run in the other (`Syntax error: "(" unexpected` or `cannot execute binary file`). Run `make -C cpp clean` before switching between them.
- A worker prompt also says "no formatter or linter write on files you do not own": in loop 20 a Rust worker ran `cargo fmt` on the whole crate and had to restore 11 files from `git show HEAD:path`; the crate is not rustfmt-clean at HEAD and CI runs no clippy.
- Long runs on this Mac: `setsid` does not exist (launch the script as a harness background task), a subagent's output file is a symlink (`stat -L` in a heartbeat), monitors and `perl -e alarm` count wall time across laptop sleep (re-arm, or wait on one single-shot until-loop), and a network drop kills subagents (`ENOTFOUND`; resume them with SendMessage) and large downloads (`unexpected EOF` in the ESP Arduino target: re-run the stage).
- Go is not installed on this Mac: run it only in `golang:1.27` (`docker run --rm -v "$PWD":/src -v packbin-gomod:/go/pkg/mod -v packbin-gocache:/root/.cache/go-build -w /src/go golang:1.27 sh -c 'gofmt -l . && go vet ./... && go test -race -count=1 ./...'`, about 30 s; the two named volumes keep the module and build caches). A test-script regex on `go test` output must allow a tab (`ok<TAB>pkg`), the 1 s AC-10 bound is asserted without `-race` only, and the ring builds the Go driver for the host with `ring-go.sh` (cross-compiled in the container).
- Swift on this Mac has Command Line Tools only (no XCTest, `Testing` not found by default): the tests use swift-testing, and every local `swift test` appends `-Xswiftc -F -Xswiftc $F -Xlinker -rpath -Xlinker $F -Xlinker -rpath -Xlinker $L` with `F=/Library/Developer/CommandLineTools/Library/Developer/Frameworks` and `L=/Library/Developer/CommandLineTools/Library/Developer/usr/lib` (else `no such module 'Testing'`, then `lib_TestingInterop.dylib` not found); one run of 48 tests takes about 11 s, the thread-sanitizer run 41 s. Only one `swift build`/`swift test` at a time in the root tree (SwiftPM locks `.build`).
- Never delete a bind-mounted path on the host right before a container starts on it: on Docker Desktop the container still sees the old entries for about a second after a host `rm -rf` (loop 28, AZ-2565: the `cpp` stage failed 6 of 12 runs, alone, with `make -C cpp clean` on the host then `docker compose run`); clean inside the container, as `scripts/loop-tests.sh` does for `cpp`.
- A Monitor or `tail -f` pipeline ends in `grep --line-buffered` (or `sed -u`), never in `cut`, `head` or `sort`: in loop 31 the step 11 watcher ended in `cut -c1-260`, delivered nothing for 30 minutes and expired while the run finished; an expiry with no events is a broken watcher, so read the log file by hand (the long-jobs rule names this failure, repeated).
- `scripts/loop-tests.sh` fails its `publish-gate` stage when anything in the repository changes while the shares run (a tree manifest before and after, loop 31): edit and write no file in the repo from the start of that stage to its end (about 10 minutes); keep notes in the scratchpad and commit them after.
